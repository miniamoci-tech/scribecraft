# AGENTS.md — rules for every agent and contributor

These rules bind every AI agent and every human contributor working in this repository. They come before any task, instruction or deadline. `CLAUDE.md` holds the day-to-day working instructions. If the two ever disagree, **this file wins.**

ScribeCraft follows the conventions of its siblings in the Crafting Apps family (PdfCraft, PhotoCraft). Where those projects link to the internal **craftrules** standards, every rule a contributor here must follow is stated in this file and `CLAUDE.md`.

---

## 1. Asset policy (absolute — no exceptions)

An **asset** is any non-code material that the project includes, ships, embeds, generates for publication, or shows in its documentation. This covers:
- icons, images, illustrations, screenshots and logos;
- fonts;
- sounds, voice recordings and video;
- sample, demo and test media (dictations, interviews, recordings) that are committed or published;
- anything the app renders or plays from those.

### 1.1 Nothing from NCH products

- **Never** use icons, images, artwork, logos, UI graphics, sounds, sample dictations, help pages, translations or any other asset taken from an NCH Software product (Express Scribe, Express Dictate, FastFox, WavePad, …), installer, website, document or package.
- **Never** recreate, trace, redraw or closely imitate an NCH icon, toolbar or graphic. Our icons come from Lucide, and our visual design is our own.
- The names "Express Scribe" and "NCH" are trademarks of their owner. They appear in this repository only to describe compatibility and parity targets (`parity/`, `docs/`), never as the product name, in the UI, in package metadata or in marketing.
- Screenshots of Express Scribe exist only as private, local observation notes under `plan/scribe/`, which is gitignored. They must **never** be committed, published, linked, shown in docs, used as a design source to trace, or placed anywhere else in the repository or its outputs.
- The only NCH-authored material allowed is **none**. Adding anything to this list needs the user's explicit approval.

### 1.2 Only open, provable licences

Every asset must be one of:
- **Open source:** ISC, MIT, BSD-2-Clause, BSD-3-Clause, Apache-2.0, OFL-1.1, Ubuntu-Font-1.0 or Bitstream-Vera.
- **Creative Commons:** CC0-1.0, CC-BY-4.0 or CC-BY-SA-4.0.
- **Public domain.**
- **Contributor-original:** created, recorded or generated by a contributor who owns it and licenses it under the project licence (`MIT OR Apache-2.0`).

Anything else is forbidden, including assets whose licence you cannot prove from the source. Examples:
- system fonts and system sounds that are not openly licensed;
- emoji artwork from Apple, Microsoft or Samsung;
- stock audio, stock photos, "free for personal use" material;
- **recordings of real people who did not consent to publication**, and any real dictation, interview, medical, legal or court recording — even "anonymised";
- screenshots of other people's software.

**Test media is synthetic.** Fixtures are generated in code (tones, chirps, noise, clicks; `scribecraft-testkit` once it exists) or recorded by a contributor reading text they wrote, with an explicit `ATTRIBUTION.toml` entry. Generated fixtures are preferred: they are reproducible and carry no personal data.

**Screenshots of ScribeCraft** are contributor-original. Everything visible in them must itself be allowed: our UI, Lucide icons, OFL fonts, and demo dictations built only from allowed assets. Never screenshot a job list that shows real file names, client names or e-mail addresses.

### 1.3 Every asset is attributed

- **`ATTRIBUTION.toml`** (repo root) is the single source of truth. It has **one entry per asset file**, whether committed, vendored, fetched at build time or bundled through a Cargo dependency. Each entry records:
  - path or URL, title, author;
  - source (URL, with version or commit);
  - SPDX licence, and the licence file in the repo;
  - SHA-256 (for files in this repository);
  - how it is used.
- **`NOTICE`** keeps the licence notices that the licences require.
- **`cargo xtask assets`** runs in `cargo xtask ci`. It fails if:
  - an asset file in the repository has no entry;
  - an entry's hash does not match;
  - a licence is not on the allowlist;
  - a licence file is missing;
  - an entry names NCH as author or source.

### 1.4 Fonts live in craft-fonts

- Font assets shared by the Crafting Apps live in [`storytold/craft-fonts`](https://github.com/storytold/craft-fonts), not here. **Never commit a font file to this repository.**
- craft-fonts is an **optional build input**, never a Cargo dependency (`CRAFT_FONTS_DIR=<checkout>`). Without it ScribeCraft builds, tests and runs.

### 1.5 Procedure for adding or changing an asset

Fonts go to craft-fonts instead (§1.4).

1. Find an asset under an allowed licence from its **original source**: the author's repository or a release, not a random mirror. Record the exact version or commit.
2. Confirm the authorship. It must not be NCH (§1.1). Keep the licence text.
3. Add the file together with its licence file, plus an `ATTRIBUTION.toml` entry. Run `cargo xtask assets`.
4. If an asset's origin or licence is unclear, **do not add it.** Ask the user.

If you find an asset that breaks these rules, stop and remove it from the repository and every output, including docs, screenshots and generated media. Then tell the user at once.

## 2. Clean-room rules (summary; details in `CLAUDE.md` and `plan/adr/0001`)

- Never read, disassemble, decompile, hex-dump, hook or copy anything inside the Express Scribe installation (on Windows `C:\Program Files (x86)\NCH Software\Scribe\`, on macOS `/Applications/ExpressScribe*.app`). Only file **names and listings** are allowed. **Never open the bundled `Help/` folder or `*.dll`/`*.exe` contents**; read the same help on the public website instead.
- Never read Express Scribe's settings, registry keys (`HKCU\Software\NCH Software\Scribe`) or its data folders: they hold the user's dictations and client data.
- Behaviour comes only from public specifications (RIFF/WAVE, ISO MP4, Ogg, FLAC, USB HID), public documentation (nch.com.au pages, published reviews and tutorials) and black-box observation of the running program with synthetic input.
- Proprietary dictation codecs (DSS/DS2, DCT, DVF, MSV, encrypted dictations) are implemented only from public specifications or not at all. Never port a vendor SDK, and never run one in-process; an external decoder the user installed may run only as a separate process (oracle pattern).
- Never copy GPL/AGPL code. Copyleft tools (FFmpeg builds with GPL parts, SoX, Audacity) run only as external oracle processes, never linked.
- Observe Express Scribe only with synthetic fixtures. Never capture personal data, real dictations, client lists, e-mail or FTP account settings.

## 3. Agent control (automation and MCP)

- **Everything is reachable headlessly.** Every user-facing feature must be callable without the GUI: an engine API, then a tool in `crates/automation` (`scribecraft-cli run` and the future MCP server use the same table). A feature is not done until its tool exists and has an end-to-end test.
- **The UI control channel is opt-in.** It runs only when the app is launched with `--control <file>`. It binds to loopback, uses a fresh random token per launch, and writes it to an owner-only file. Never enable it by default, widen the bind address, or log the token.
- **The MCP server is opt-in.** Never make the app, the CLI or an installer start it, register it with an agent, or listen on a port by default.
- **Safe by default.** Tools must never discard unsaved work silently, must write atomically, must honour `--root`, and must return errors an agent can act on (say what was wrong and what is allowed).
- **No outbound network by default.** Dictation intake from FTP, e-mail or the network (Express Scribe parity) is opt-in per source, configured by the user, and never enabled by an agent or an installer. Adding any network access is the owner's decision.
- **Track parity honestly.** Every user-facing feature has an entry in `parity/express-scribe-features.toml`. Mark it `shipped` only when it works end to end and the entry cites a passing test (`evidence`); `cargo xtask parity` (part of `xtask ci`) rejects claims whose tools or tests don't exist.
- **Use it to test.** Agents drive the engine through `scribecraft-cli run --script` and check `transport_render` output (a WAV of exactly what the listener would hear) to verify their own changes.

## 4. Never crash

ScribeCraft opens recordings from strangers, and transcriptionists trust it with hours of work. A malformed MP3, a bad tool argument, a corrupt job list, an unplugged foot pedal or a full disk must produce an error the user (or agent) can act on, never a crash and never lost work. **This outranks feature work.**

- **Fail with `Result`.** Non-test code returns errors through the crate's error type and `?`. Where readers are lenient by design, fall back gracefully and record the repair.
- **No panicking shortcuts.** No `unwrap()`, `expect()`, `panic!`, `unreachable!`, `todo!` or `unimplemented!` outside tests, unless the call is provably infallible, with a comment saying why. `assert!` only for internal invariants that input cannot reach.
- **No `unsafe`.** The workspace sets `unsafe_code = "forbid"`. If a platform API needs it (audio devices, HID pedals, global hotkeys), use a maintained safe wrapper crate.
- **Treat every input-derived number as hostile.** Sample rates, channel counts, durations, frame counts, seek positions and speeds come from files or users. Use `get()` instead of `[i]`, checked/saturating arithmetic, guard against division by zero and NaN/inf casts, never cast a negative value to `usize`, and cap allocations sized by the file (`scribecraft_media::Limits`).
- **Bound recursion and loops.** Folder scans follow no symlink cycles and stop at a depth limit.
- **Don't cascade.** Handle lock poisoning (the audio callback shares the transport with the UI), and keep a panic in the audio or decoding thread from taking the app down or losing the job list.
- **Prove it.** Every crash fix comes with a small synthetic regression test that failed before the fix.
- **Enforced by clippy.** The workspace `[workspace.lints]` table denies `unwrap_used`, `expect_used`, `panic`, `unimplemented`, `todo` and `unreachable`, and warns on `indexing_slicing` (an error under `-D warnings`); every crate opts in with `[lints] workspace = true`. Root `clippy.toml` lets tests use them.

## 5. Privacy of dictations

Dictations are often medical, legal or HR recordings. Beyond §1 and §2:
- Never log audio content, transcripts, file names of user dictations or job metadata at `info` level or above.
- Never send dictations, transcripts or job lists anywhere unless the user configured that destination.
- Crash reports and diagnostics contain no file paths under the user's home and no job metadata.

## 6. Everything else

Follow `CLAUDE.md`. It covers quality gates, layering, commit rules and how to run and listen to the app.
